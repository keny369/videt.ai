## Authority

This matrix is the controlling source for Pass B. It carries no product authority of
its own: every row is derived from an accepted Volume I acceptance criterion and cites
the governing source it came from. Where this matrix and Volume I disagree, Volume I
prevails and this matrix is defective. Under PM-REQ-003 authority is resolved by scope
before rank: Volume I owns product behaviour, the Engineering Manual owns engineering
practice, and Volume II owns product-specific implementation contracts only.

## Derivation

This file is generated by `scripts/build_volume_ii_matrix.py` from the accepted Volume I
corpus. Coverage is therefore a property of the source rather than of authoring
diligence: every acceptance criterion in `ACCEPTANCE_AND_TEST_MAPPING.md` becomes exactly
one row, and every row names the criterion it was derived from. Re-running the generator
against an unchanged Volume I MUST reproduce this file byte for byte.

Pass B fills the technical contract fields per row. It MUST NOT add a row that no Volume I
source governs, and MUST NOT remove a row without a controlled Volume I change.

## Column Meanings

- `Row`: stable matrix row identifier. Rows are never renumbered.
- `AC`: the governing Volume I acceptance criterion. Exactly one per row.
- `Source`: the Volume I artefact that owns the criterion.
- `PR-REQ`: product requirements reaching this row, via the Volume I traceability matrix.
- `CAP` / `WF` / `PRULE`: governing capability, workflow and product rules.
- `OD`: owner decisions the row depends on, resolved or pending.
- `EM`: Engineering Manual volumes governing how the row is built, never what it does.
- `Slice`: implementation slice. `ALL` marks a cross-cutting rule enforced in every slice.
- `Tests`: planned verification types from Volume I.
- `Status`: `Pass B required` until its contract fields are supplied.
- `Blocker`: a live upstream blocker, or `None`.
