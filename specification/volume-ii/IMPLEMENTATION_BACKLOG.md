## Authority

This backlog carries no product authority. Every item is a matrix row, every matrix row is
derived from an accepted Volume I acceptance criterion, and the contract named by each item
is the thing to be implemented. Where this backlog and a contract disagree, the contract
prevails and this backlog is defective. It invents no feature: an item that no acceptance
criterion governs cannot exist here, by construction.

## Derivation

Generated by `scripts/build_implementation_backlog.py` from `SLICE_REGISTER.md`,
`IMPLEMENTATION_MATRIX.md` and the per-slice contract sources. Re-running it against an
unchanged specification MUST reproduce this file byte for byte, and
`--check` fails if it differs. Do not edit this file by hand.

Order is the slice dependency graph, topologically sorted. Cross-cutting (`ALL`) rows are
listed last because they are enforced in every slice rather than implemented once; they are
not the final work, they are the work that is never finished early.

## How To Use An Item

An item is done when its acceptance criterion passes, and not before. Read in this order:

1. the **acceptance criterion** in `../volume-i/ACCEPTANCE_AND_TEST_MAPPING.md` — the oracle;
2. the **governing source** — the capability, workflow or product rule that owns the behaviour;
3. the **contract** — the 40 structured fields naming exactly what to build;
4. the **verification obligation** — the test types Volume I requires.

A `Withheld limb` line means one named behaviour is reserved by a pending owner decision.
Build everything else; never effect the limb, and never resolve it by inference. The
surrounding behaviour is specified and testable.
