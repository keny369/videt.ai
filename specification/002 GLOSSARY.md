# 002 GLOSSARY

## Document Control

- Status: Accepted baseline
- Version: 1.0.0
- Last updated: 2026-07-15
- Owner: Chief Architect
- Classification: Canonical

## Purpose

Provide canonical definitions for business, product, architecture and AI concepts used throughout Project F1 documentation.

## Scope

This glossary defines concept meanings. Naming conventions and wording rules are governed by [003 TERMINOLOGY.md](003 TERMINOLOGY.md).

## Glossary Terms

### Account

A customer organization that owns one or more domains and users within Project F1.

### AI Assistant Surface

A discovery surface where an AI system synthesizes answers, such as ChatGPT, Claude, Gemini or Perplexity.

### AI Presence

A score pillar measuring how often and how accurately a domain appears in AI-generated answers for relevant intents.

### Architecture Decision Record

A durable record of a significant decision, alternatives considered and consequences. Stored in [../DECISIONS.md](../DECISIONS.md).

### Baseline Scan

The first full assessment of a domain used to establish initial score and issue inventory.

### Canonical Definition

The single authoritative definition for a concept. All other documents must reference it.

### Check

A deterministic or model-assisted evaluation applied to collected evidence.

### Check Result

Structured output of a check, including status, evidence pointers and severity.

### Competitor Benchmark

Comparative score and issue context against peer organizations or domains.

### Confidence

Estimated reliability of a finding or recommendation based on available evidence quality.

### Crawl

Automated process that collects site pages, metadata, links and structural signals for analysis.

### Crawl Budget

Bounded limit for how many URLs and resources are fetched in a run.

### Discoverability

The probability that a business is found and selected across search and AI answer surfaces for relevant intent.

### Discoverability Intelligence Platform

Project category definition describing a system that measures, explains and improves discoverability continuously.

### Discoverability Score

Normalized score from 0 to 100 representing overall discoverability based on weighted pillar performance.

### Domain

A customer web property under analysis, typically represented as one or more Sources inside a Project.

### Domain Event

A versioned, named business event describing a meaningful state change in a canonical domain concept.

### Evidence

Collected data used to support checks, scoring and recommendations.

### Finding

A detected issue or opportunity derived from evidence evaluation.

### Foundation Documents

The immutable baseline documents numbered 000 to 020 that define shared rules, terms and principles for all later chapters.

### Implementation Artifact

A delivery-ready output that helps execute a remediation, such as patch guidance, snippet, checklist or prompt.

### Issue

Canonical term for a prioritized finding requiring action. In customer outputs, issue and finding may be displayed together.

### Issue Priority

Relative execution order based on expected impact, confidence and effort.

### Local Presence

A score pillar measuring visibility and consistency in location-based discovery channels.

### Monitoring Run

Scheduled re-evaluation of a domain to track score and issue changes over time.

### Non-Invasive Remediation

Operating model where the platform provides recommendations and artifacts but does not directly modify customer production systems.

### Pillar

A major dimension of the Discoverability Score. Current pillars are Technical Integrity, Search Presence, AI Presence, Authority Signals, Trust Signals, Content Quality and Local Presence.

### Platform Recommendation

A structured, prioritized action generated by the platform with rationale and implementation guidance.

### Prompt Version

Tracked version identifier for an LLM prompt template used in production workflows.

### Project

A bounded discoverability program for an organization, used as the primary planning and evaluation unit.

### Recommendation Artifact

Stored output package tied to an issue and generated for implementation by a user or partner team.

### Score Snapshot

Point-in-time storage of overall and pillar scores with version metadata.

### Search Presence

A score pillar measuring visibility and performance across traditional search channels.

### Source

A configured input location within a Project used for crawl or ingestion scope.

### Strategic Non-Goal

An explicitly rejected objective used to prevent scope drift and preserve architecture intent.

### Technical Integrity

A score pillar measuring structural and technical site quality impacting discoverability.

### Trust Signals

A score pillar measuring credibility indicators affecting ranking and answer inclusion confidence.

### Value Metric

Primary usage or outcome metric used to align pricing with customer value.

### Volume

A major manual section grouping related architecture domains, for example Volume I or Volume IV.

## Definition Governance

- New terms must be added here before use as canonical language.
- Modified definitions require an ADR entry and dependent document updates.
- If a term appears in multiple chapters, this glossary controls meaning.

## Acceptance Criteria

1. all critical product and architecture terms are explicitly defined
2. definitions are unambiguous and implementation-oriented
3. governance rule for adding and changing terms is explicit
